What this needs that the app does not have A running sum needs the stops in route order, and a stop's identity is deliberately its normalised name rather than Metro's row order (ADR-0013), so nothing in the payload says which stop comes next. Recovering it means joining stop_times.txt, which the roadmap already names as the way direction could come back. Direction is collapsed, so one width per segment is both directions added together, not a train's load. Drawing it as a single band claims more than the data says unless the label says so. The profile should close at zero and will not. Stop sums miss line totals by a median 0.06% and up to 5.10%, one-sided upward, so whatever the sum has left at the terminus is the accumulated error — which makes this chart a useful data check as well as a picture.
